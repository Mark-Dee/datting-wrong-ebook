# Dating Wrong — digital book platform

React + Vite frontend, Express API (as a Vercel Function), Firebase Auth + Firestore.

```bash
npm install
cp .env.example .env      # fill in values (see comments inside)
npm run dev               # http://localhost:3000   (no service account => NON-durable memory store, with a warning)
npm test                  # 19 API tests (in-memory backend)
npm run lint              # tsc --noEmit
npm run build             # Vite frontend in dist/ (API function is deployed from api/index.js)
```

## How it fits together
| Part | Where |
|---|---|
| API (all routes) | `server/app.ts` (`createApp()`) |
| Local / self-hosted server | `server.ts` |
| Vercel Function entry | `api/index.js` (checked-in deployment bundle) |
| Persistence (Firestore) | `server/persistence.ts`, `server/firebaseAdmin.ts` |
| Auth (Firebase ID tokens) | `server/auth.ts` |
| Book text (server-only) | `server/book/` — never imported by `src/` |
| Browser-safe preview data | `src/data/publicBook.generated.ts` (generated by `npm run generate:public-book`) |
| Firestore rules | `firestore.rules` (deploy with `firebase deploy --only firestore:rules`) |

The Vercel build compiles the browser app only. The API function bundle is deployed from `api/index.js`; the checked-in `src/data/publicBook.generated.ts` supplies browser-safe preview data.
`functions/` (Firebase Cloud Functions) is unchanged and independent of the Vercel deployment.
